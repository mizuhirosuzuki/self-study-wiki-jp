# Lint — wikiの健全性チェック

wikiが育つと矛盾や抜けが出る。定期的に全体を点検し、直せるものは直し、新しく調べるべきことを提案する。

## 手順

1. `index.md`、`wiki/log.md`、`wiki/concepts/*.md` をすべて読む。
2. 次の観点で点検する:
   1. **矛盾**: ページ間で食い違う主張・定義・数式。
   2. **古い記述**: 後の質問・新しい情報で置き換わったのに残っている主張、`## 概要` とQ&Aの不一致。
   3. **孤立ページ**: 他のどのページ・indexからもリンクされていないページ。
   4. **未作成の重要概念**: 複数ページで言及されているのに専用ページがない概念。
   5. **相互参照の欠落**: 関連が明らかなのにリンクがない、片方向リンクのみ。
   6. **情報の欠落**: Web検索（WebSearch/WebFetch）で補える不足（定義の別流儀、歴史的背景、証明の補足など）。教科書外の情報には出典URLを付け「補足」と明示する。
   7. **index不整合**: 未掲載ページ、リンク切れ、要約が古い、Q&A数・更新日のずれ。
   8. **書式**: frontmatter欠落、`CLAUDE.md` の書式違反、ファイル名規則違反。
3. **レポートを出力する**（重大度順: 矛盾 > 古い記述 > 孤立/欠落 > 書式）。各項目に該当ページへのリンクを付ける。
4. **修正を適用する**:
   - 機械的で意味が変わらないもの（リンク追加、index同期、frontmatter補完、リンク切れ修正）は、そのまま適用する。
   - 内容が変わるもの（矛盾の解消、記述の書き換え、ページの統合・分割・新規作成）は、案を提示してユーザーの了承後に適用する。
   - `raw/` は決して編集しない。
5. **次の一手を提案する**: 調べると良い新しい質問、読むべき章、探すべき資料（3〜5件）。
6. `wiki/log.md` に `- YYYY-MM-DD lint: <発見N件 / 修正M件>` を追記し、`index.md` を最終的に同期する。
